## Findings

### F-0001: Sensitive Information Disclosure - Application Configuration and OAuth Credentials Exposed

**Severity:** HIGH  
**CVSS Score:** 7.5 (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N)  
**CWE:** CWE-200: Exposure of Sensitive Information to an Unauthorized Actor

#### Description

The application exposes sensitive configuration information through the `/rest/admin/application-configuration` endpoint without requiring authentication. This endpoint reveals critical security information including OAuth credentials and account recovery data.

#### Technical Details

**Affected Endpoint:** `GET /rest/admin/application-configuration`

**Exposed Information:**

1. **Google OAuth Client ID:**
   - `1005568560502-6hm16lef8oh46hr2d98vf2ohlnj4nfhq.apps.googleusercontent.com`
   - This could be used in phishing attacks or OAuth abuse

2. **Security Question Answers:**
   - Account recovery question answer: "Daniel Boone National Forest"
   - Account recovery question answer: "ITsec"
   - These allow attackers to bypass password reset security

3. **Application Configuration:**
   - Server configuration details
   - Internal paths and file locations
   - Product and inventory data
   - Memory/image metadata

#### Impact

An attacker can:

- Harvest OAuth client IDs for phishing or credential stuffing attacks
- Bypass account security questions to reset passwords and take over accounts
- Gather reconnaissance information about the application architecture
- Potentially access additional administrative functions

#### Proof of Concept

```bash
curl http://localhost:3333/rest/admin/application-configuration
```

The endpoint returns the complete application configuration including sensitive credentials without any authentication required.

#### Remediation

1. **Immediate Actions:**
   - Remove the `/rest/admin/application-configuration` endpoint from public access
   - Implement authentication and authorization checks for all admin endpoints
   - Rotate exposed OAuth credentials immediately

2. **Long-term Fixes:**
   - Store OAuth secrets server-side only, never expose to clients
   - Remove security question answers from any client-accessible configuration
   - Implement principle of least privilege for configuration access
   - Add API authentication middleware to protect sensitive endpoints
   - Conduct security review of all REST endpoints to identify similar issues
